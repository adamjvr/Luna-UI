# C2.5D2R — Luna partial-damage runtime integration repair

C2.5D2 committed the framebuffer region-copy API, damage-report fields, and
focused tests. The Kitchen Sink renderer itself remained on the earlier
whole-frame cached-animation route.

C2.5D2R completes the runtime integration.

## Completed path

For an animation-only frame with a compatible static cache, Luna now:

1. classifies cache eligibility before rebuilding general scene layout;
2. advances the logical animation clock;
3. computes the previous and current square rectangles;
4. includes the changing HUD rectangle;
5. restores only those regions from the static backing framebuffer;
6. redraws the current square and HUD;
7. reports `.partialDamage` with region and pixel counts.

The cached layout is stored with the static backing frame, so the fast path does
not reconstruct the editor shell, pane surfaces, menu definitions, or static
proof geometry.

## Cache generation

The proof cache records:

- framebuffer size;
- demo mode;
- canonical theme name;
- the layout used to create the static backing frame.

Resize and theme replacement clear both the cache and the previous-square damage
anchor. Mode or theme-generation mismatch, active transient overlays,
selection-autoscroll, and non-animation invalidations use the complete path.

## Statistics repair

`LunaFrameTimingStats` now counts `.partialDamage` alongside
`.cachedAnimation` when calculating cache eligibility and cache-backed hit rate.
