# C2.5G — Measured Runtime Attribution

C2.5G closes the gap between requested runtime policy and the work the host
actually performs. It does not guess that renderer creation flags were honored,
and it does not infer event-loop behavior from CPU percentage alone.

## What is measured

The Linux SDL host records:

- SDL renderer name, returned renderer flags, and whether present VSync is
  actually reported by `SDL_GetRendererInfo`;
- host-loop and native polling iterations;
- raw native and translated semantic event counts;
- bounded semantic dispatch slices and the largest deferred event count;
- invalidation-driven and continuous frame requests;
- full-scene, partial-damage, cached-animation, and unattributed frames;
- render and present nanoseconds;
- idle and software-pacing sleeps.

Set `LUNA_RUNTIME_TRACE_PATH` to write a sorted, human-readable JSON snapshot at
normal process exit:

```bash
LUNA_RUNTIME_TRACE_PATH="$PWD/luna-runtime.json" \
  swift run LunaUITestApp -- --editor
```

## Correctness changes

`LunaSDLPresenter.usesVSync` now reflects the renderer flags SDL returned rather
than merely echoing the requested configuration. If VSync was requested but not
provided, Luna's software frame pacer remains active.

The Luna demo also reuses one revision-keyed static-text presentation and one
virtualization context across both editor panes. A document edit creates one new
presentation; repeated pane layout for the same revision is a cache hit.

## Acceptance gates

1. `swift build`, focused tests, full tests, and `validate-iteration.sh` pass.
2. Editor traces show no continuous frame requests while idle.
3. Kitchen-sink traces identify continuous animation separately from native
   backlog and semantic dispatch.
4. Requested and actual VSync fields are visible in the trace.
5. A large-document native run shapes viewport-bounded rows rather than the
   complete document.
6. No merge to `main` occurs until the paired Moth delivery pins the exact Luna
   commit and both native acceptance checklists pass.
