# C2.5H — Lazy UTF-8 Line Index

## Problem

C2.5G made shaping and paint work viewport-bounded, but `LunaStaticTextDocument`
still eagerly split the complete source into one separately allocated `String` per
logical line. Every Moth edit creates a new immutable presentation revision, so a
50,000-line file repeatedly paid for 50,000 line-string allocations before the
viewport could render.

`location(forAbsoluteUTF8Offset:)` also scanned every line sequentially.

## Change

C2.5H stores one source string plus a compact UTF-8 line-slice index. It adds:

- lazy line-string materialization through the existing line subscript;
- metadata-only access through `lineMetadata(at:)`;
- an indexed `utf8Count` property;
- O(log line-count) absolute-offset lookup;
- compatibility `lines` projection only for callers explicitly requesting every line.

The virtualization context now consumes the indexed UTF-8 count rather than
recounting the complete source.

## Gate

The full Luna suite must pass. The C2.5H tests must validate 50,000-line metadata,
Unicode/trailing-newline behavior, exact offset mapping, and viewport-bounded
geometry work.
