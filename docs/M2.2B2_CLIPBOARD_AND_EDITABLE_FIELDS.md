# M2.2B2 Luna Support — Clipboard and Editable Fields

Moth Text M2.2B2 exposed two reusable framework requirements.

## Clipboard host boundary

`LunaClipboardService` is a plain-text capability interface. It deliberately
contains no editor command or mutation policy. Applications decide what Copy,
Cut, and Paste mean and must handle runtime read/write failures.

`LunaInMemoryClipboardService` provides deterministic headless tests, including
one-shot read and write failures. `LunaSDLClipboardService` maps the contract to
SDL on Linux.

## Editable field state

`LunaEditableFieldState` is a reusable single-row value type with UTF-8 byte
offsets snapped to extended-grapheme boundaries. It owns field-local caret,
selection, navigation, insertion, and deletion. It does not access a system
clipboard or issue product commands.

The generic Luna Find/Replace panel now composes two editable field states and
renders their caret/selection geometry. Products continue to own search,
replacement, undo grouping, and document targeting through the existing session
boundary.

## SDL application identity

`LunaSDLApplicationConfiguration` accepts optional application identity and
window-class strings. The host exports the appropriate SDL/X11/Wayland hints
before SDL initialization. Product identifiers remain supplied by the
application, not hard-coded in Luna.
