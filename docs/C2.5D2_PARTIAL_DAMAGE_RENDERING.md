# C2.5D2 — Partial-damage rendering

C2.5D2 turns the C2.5D frame-path measurements into a real bounded rendering
path.

## Kitchen Sink animation

An animation-only frame no longer:

- rebuilds complete scene layout;
- rebuilds menu state;
- copies the complete cached framebuffer.

The static cache now retains the layout geometry required by dynamic surfaces.
The animation path restores only:

1. the previous moving-square rectangle;
2. the current moving-square rectangle;
3. the HUD rectangle.

It then redraws the current square and HUD and reports `.partialDamage`.

## Cache generation

The cache records:

- framebuffer dimensions;
- demo mode;
- canonical theme name;
- the static layout used to render the backing frame.

Resize, theme replacement, mode mismatch, transient overlays, non-animation
invalidation, and selection autoscroll force the complete path.

## Framebuffer API

`LunaFramebuffer.copyPixels(from:in:)` performs clipped rectangular copies and
returns the actual number of pixels copied. Multiple distant regions remain
separate, avoiding a large bounding-box copy.

## Deliberate limit

This checkpoint does not yet change SDL input scheduling. It reduces animation
and text-update rendering cost first, so the following fairness checkpoint can
measure host scheduling without full-frame noise dominating the result.
